ID: WK2-OBSERVATION

VISUAL RECONSTRUCTION: REAL-TO-SIM

Implementation documentation for the Week 2 learning plan.

1. Introduction

TARGET: OBSERVATION LAYER

This document details my implementation of a Real-to-Sim observation layer for Week 2. I utilized photogrammetry techniques to reconstruct a 2D image dataset into a scaled 3D model, preparing the geometry for integration into a physics simulator.

2. Camera Calibration (Phase 1 & 2)

LIB: OPENCV INPUT: 14 CALIB IMAGES

To eliminate lens distortion and prevent mathematical errors during 3D projection, I performed an intrinsic camera calibration. I printed a standard checkerboard pattern and captured 14 images from various angles.

Using OpenCV, I developed a Python script to detect the checkerboard corners, successfully extracting the camera matrix and distortion coefficients required for the reconstruction phase.

3. Data Collection (Phase 3)

TARGET: RIGID OBJECT INPUT: 38 SCENE IMAGES

For the target reconstruction, I selected a highly textured LEGO block. To ensure the feature-matching algorithm had enough reference points, I placed the object on a handwritten notebook, providing dense background texture.

I captured a 360-degree orbital dataset consisting of 38 images. I also measured the physical length of the LEGO block (6.5 cm) and recorded it in a configuration file for later metric scaling.

4. 3D Reconstruction (Phase 4)

LIB: PYCOLMAP OUTPUT: SPARSE POINT CLOUD

I implemented the Structure from Motion (SfM) pipeline using the PyCOLMAP library. I configured a Python script to execute three core algorithms sequentially:

  • Feature Extraction: Detecting unique keypoints across all 38 images.
  • Feature Matching: Exhaustively matching keypoints to find overlapping visual data.
  • Bundle Adjustment: Solving the nonlinear optimization problem to estimate camera poses and 3D point coordinates.

The pipeline successfully registered 37 out of 38 images into a unified 3D space, generating a sparse point cloud containing 4,164 points.

5. Metric Scaling & Validation (Phase 5 & 6)

MATH: SIM3D TRANSFORM ERROR: 0.95 PX

Since SfM reconstructs scenes in an arbitrary, dimensionless coordinate system, I developed a scaling script. It parses the 6.5 cm physical measurement, computes the relative scale factor, and applies a 3D Similarity Transform to all points and camera poses.

To mathematically validate my reconstruction, I wrote a reprojection script. It takes the newly generated 3D points and projects them back onto a 2D source image using the calculated Rotation matrix, Translation vector, and Camera intrinsic matrix.

The validation succeeded: the reprojected green dots aligned precisely with the physical object in the photograph, yielding a mean reprojection error of just 0.95 pixels.

6. Export for Simulation (Phase 7)

FORMAT: PLY, URDF TARGET: PYBULLET / MUJOCO

As a final step to prepare the asset for robotics physics engines, I wrote an export module. This module parses the internal COLMAP binary structure and exports the geometry as a standard PLY point cloud.

Additionally, it generates a URDF (Unified Robot Description Format) XML file, allowing the geometry to be loaded dynamically into simulators like PyBullet or MuJoCo.
